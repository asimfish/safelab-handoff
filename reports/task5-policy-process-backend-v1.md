# SafeLab 独立执行器进程后端 v1

实现目录：`/home/liyufeng/ops/safelab_5b_stable_attach_20261101/throughput_20261103_v2`。
适用范围：五任务 issue #17 TTC 对齐削弱版的已交付 SDK。官方 Mem-0 使用另一种服务结构，不能直接套用此补丁；其他任务需重新做自己的固定输入与原始物理日志验收。

## 接入

1. `prepare_worker.patch()` 为原生 `Pool` 增加单 lane 构造选项；每个执行器在独立 Python 进程中加载。原生策略的 reset/step、推理算法、记忆更新和 RNG 方法保持不变。
2. `lane_gateway.py` 启动四个本机 worker，保留 `/health`、`/reset_many`、`/step_many` 接口。每个 lane 固定路由一个 worker，同 lane 串行，不同 lane 并发。每个 Isaac 进程仍只有一个环境：**N1×k 多进程并行**。
3. 调用端逐条发送连续15Hz观测。保持原 lane、reset、种子、frame_index 和任务身份；请求结果未知时不能重试推理，以免重复推进记忆或随机数。
4. 用 `prepare_queue.py` 生成新的不可变启动包，不改运行中的目录。2026-11-03 已冻结旧全量队列，`activation_guard.py` 的旧自动激活入口禁用；新评测只有满足 SafeLab-Eval-v1 准入后才可派发。

## 对照与实测

- 执行器组件：四个 B1 lane，执行4/8/30步，108组数组逐项完全相同；分进程组件吞吐为串行的2.11–2.16倍。证据 `RESULT.json`。
- 完整策略：包含真实 next/DAG Planner、Gen、原生策略，固定 RGB、13维关节、指令、历史及随机种子。每个模式864个请求，3轮预热、6轮计时；动作和语义输出完全一致。只从比较中去掉随机生成的 `planner_event.request_id`，不忽略模型输出。
- 完整策略提速：h4 **1.564倍**，h8 **1.551倍**，h30 **1.550倍**。证据 `PIPELINE_RESULT.json`；对照实现 `pipeline_probe.py`、`comparison.py`。
- 组件并发窗口 GPU 利用率80–92%，串行窗口18–23%。这不是整段仿真的平均值。
- 现有双卡Pro仅使用自有GPU0进行48条原生试批，N1×4；另一张卡的其他任务保留。07:34的采样约79,410/97,887MiB、73%利用率；08:07采样约75,435MiB、50%。主机资源与其他工作共享，所以不能把固定输入1.55倍直接当作完整物理评测提速。

## 物理验收与边界

48条试批保持原始控制、相机、场景、物理验收和逐tick审计，成功与失败都保留原始物理结果。10:20 UTC核对发现试批已因共享主机内存不足保护而终止：12条已有闭环结果、4条中断、32条未派发；这不是48条验收通过。原始运行目录的 OWNED_CLEANUP.json 通过，进程检查未发现本试批和图像对照残留进程；其他任务未停止。已闭合结果继续只读审计，中断条按基础设施未知处理，不作为模型失败。后端暂不切换正式评测，也不自动重启旧矩阵。

固定输入等价与提速对照已通过，完整物理放量准入仍未通过。下一次试批需有足够独立主机内存和共享内存余量，并保留两种条件下的原始审计；每个模型组合仍须通过训练输入、专家回放、开环预测和20条冒烟准入。不能把固定观测结果计作模型任务成功率。

原生控制保持15Hz观测、120Hz物理、30×13绝对目标预测，正式新增仅执行4/8步。实时日志写本地盘，归档异步；共享盘复制失败只标“待归档”，不终止仿真。当前旧试批不会被热改代码；后续启动器必须执行此归档规则。
