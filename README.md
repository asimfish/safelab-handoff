# SafeLab 训练与评测交接表

https://asimfish.github.io/safelab-handoff/

只维护一张主表。每行是一个任务 / 数据版本 / 相机 / 方法的训练记录或具体权重，列出：

- 训练数据路径与版本
- 方法、权重路径与训练步数
- 训练 / 交付状态、是否评测
- 执行4步、8步和30步的成功率、样本数及验收口径

## 新增和修改

点击「新增一行」或行尾「编辑」，填写后通过 GitHub 登录并确认提交交接单。
仓库协作者提交后生效；外部提交需维护者添加 `safelab-approved` 标签。
返回表格点击「刷新数据」，其他人也会看到同一份共享记录。

可以先登记「训练中」，步数填0，权重与成绩留空。尚未确认的数据版本/相机也可明确留待确认。
十任务 TTC 当前仅是用户提示的训练中待确认条目，不代表权重已交付或有评测结果。

修改已有权重的路径、版本、相机、方法或训练步数会另存一行，并保留原权重与原成绩。
旧成绩不自动继承；同一数据版本的路径修改会同步到使用该版本的其他行。
行尾「详情」保留原始交付配置、完整路径、历史评测和单独标注的诊断结果。

## 数据与权限

`data.json` 为核对后的基线；GitHub Issues 为团队共享编辑记录。
网页不保存 Token。只有 OWNER / MEMBER / COLLABORATOR 或维护者批准的记录进入主表。
同一行多个更新按更新时间归并；原始验收成绩保持可追溯。
关闭交接单不删除记录；`safelab-archived` 标签将其移出共享覆盖层。

手动刷新与每5分钟同步均重读已发布基线和共享交接单；会话历史并非自动轮询。
GitHub暂时不可用时明确显示错误，并保留可用的发布基线。

验证：`node --test tests/model.test.js`；本地8770端口启动静态服务后运行
`node tests/browser-qa.mjs`。发布源为 `docs/publish` 分支根目录。
